# Legendary flight cosmetics

Published prototype implementation, October 11, 2026. Four original Blender creatures are selectable plane appearances in the existing automatic battle loop. They are free to equip. Legendary is a presentation label; no product, Robux purchase, unlock requirement, or combat advantage is attached to these prototypes. Published to [Skybound Test](https://www.roblox.com/games/86507299893768/Skybound-Test), place `86507299893768`, universe `10770074500`, as **version 21** at **2026-10-11T07:35:07.714Z**. Native Studio reported successful publication. Publication preceded the source commit; the candidate hash and source parity below identify the published content.

## Try them

Open `build/Sky-Battle-Mounts-Final.rbxlx` from this checkout in Roblox Studio and press **Play**. This distinct final filename avoids reusing a cached earlier Studio document. In the hangar, use **< / >** beside the plane name to cycle through the seven choices. Select the eagle, phoenix, or manta, then press the main **PLAY** button and choose your battle cards as usual. Your pilot fights automatically on the equipped appearance.

The client animates both wings in the hangar and during flight, with smaller motion when reduced motion is enabled in battle. The saddle uses a seated clone of the player's avatar; practice opponents use a neutral pilot. The real character is never reparented or posed. Flight animation freezes when the creature is knocked out so the crash presentation can maintain consistent floor contact.

The pipeline is authored Blender model → [export_mounts.py](../assets/mounts/export_mounts.py) → optimized GLB → Studio mesh/texture import → measured import ledger → packaged templates. The exporter removes the concept rider and presentation scene. Runtime wings use rigid hinge rotations; the manta's Blender shape-key deformation and the phoenix's separate tail animation are not imported as skeletal animation.

The saved Studio import ledger retains a **12-stud input wingspan**. Its measured import conversion is a -90-degree rotation about Y; use those measured transforms when packaging, rather than the export manifest's generic GLB rotation guidance. The package script consumes the uploaded asset IDs and multiplies part sizes and CFrame positions by `16/12`, producing a **16-stud visual wingspan**. Mesh rotations and original mesh sizes remain unchanged. Seat and hinge offsets are derived from the Blender manifests at `16/source_wingspan`. Packaging does not upload assets or rewrite the import ledger. Rebuild from the existing records with:

```sh
python3 assets/mounts/package_mounts.py
python3 scripts/build.py --output build/Sky-Battle-Mounts-Final.rbxlx
python3 scripts/validate_package.py --place build/Sky-Battle-Mounts-Final.rbxlx
```

The regular `python3 scripts/build.py` also includes the templates in canonical `Skybound.rbxlx` and `build/Sky-Battle-Playtest.rbxlx`. Reopen the exact file after rebuilding. Packaging and local Studio play do not publish an experience.

## Runtime contracts

Templates live at `ReplicatedStorage.FlightGame.MountTemplates.<PlaneCatalog ID>`. Each template is a Model with an origin pivot and Body, WingLeft, and WingRight child Models. Forward is +X and up is +Y. Runtime WingLeft is negative Z; WingRight is positive Z. Glow geometry belongs to the same hinge group as the matching wing. Base visual wingspan is approximately **16 studs** before the plane's display scale, improving creature readability beside the stock aircraft.

[MountVisuals.luau](../src/shared/MountVisuals.luau) clones the template and makes all geometry anchored, noncollidable, nontouchable, and nonqueryable. [World.luau](../src/shared/World.luau) removes stock aircraft geometry and landing gear while retaining invisible Fuselage/Propeller compatibility anchors, smoke, flare, and trail support. A missing or invalid template leaves a visible Cruiser fallback with `MountVisualLoaded=false` and a diagnostic `MountVisualStatus`; validation requires real templates and rejects that fallback.

Template attributes control `CockpitX/Y/Z`, `CockpitYaw`, `PilotScale`, `FlapAmplitude`, `IdleFlapAmplitude`, and `FlapFrequency`. Angles use radians and frequency uses cycles per second. `CockpitX/Y/Z` locate the avatar HumanoidRootPart at base scale. The current package uses `PilotScale=0.6` and places the root **0.65 base studs** above the saddle position normalized to the 16-stud template. The full plane scale applies to rider and seat position together. Eagles and phoenix use a 0.4-radian flight flap amplitude at 1.25 cycles per second; the manta uses 0.28 radians at 0.85 cycles per second.

All four catalog profiles inherit Cruiser's `speed=72.25`, `angle=35`, and `defaultAngle=35` for the archived distance-flight path. Active battles retain the unchanged shared attachment positions, `BattleVisualSize=12`, and contract version 1. Mesh bounds, wingspan, rarity, paint, and rider size do not enter `BattleSimulation` or change damage, armor, hitboxes, or speed. Decoy and squadron copies preserve mesh surface appearances; attack afterimages use flat Neon silhouettes.

To repeat the fixtures, run these from the Studio **server** command bar during Play in the freshly opened final candidate:

```lua
local shared = game.ReplicatedStorage.FlightGame
local tests = game.ServerStorage
local client = game.StarterPlayer.StarterPlayerScripts
print(require(tests.PlaneCatalogTests)(require(shared.PlaneCatalog)))
print(require(tests.MountVisualsTests)(require(shared.World)))
print(require(tests.BattleViewTests)(require(client.BattleView), require(shared.World), require(shared.BattleSimulation)))
```

MountVisuals tests require all four packaged templates and check visible meshes, invisible shells, no aircraft wheels, collision/query flags, battle attachment stability, flapping, knockout freeze, resizing, and cockpit scale. BattleView tests exercise every selectable skin through Meteor, Firework, Machine Gun, and Pinball while preserving geometry and hidden shells. These fixtures do not establish asset loading in the published experience, phone performance, subjective animation quality, or rider fit across avatar proportions. Restart Play after camera fixtures before reviewing the normal hangar and battle flow.
